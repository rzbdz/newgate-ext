# 穿过 SSH 看远端界面

内网里常有一类机器：**只开 SSH**。newgate 在那台机器上照常跑着，网页界面在它的
`127.0.0.1:8899` 上听着——但从你这台机器够不到它。这个模块给出的答案是：穿过 SSH
去把它取回来。

一个模块（`modules/ssh-tunnel`），两条路，同时在：

```text
newgate tunnel add snode1 --host 10.0.50.11 --user me --remote-port 8899 --local-port 9401

http://127.0.0.1:9401/ui/                  转发端口 —— 一个字节都不动
http://127.0.0.1:8899/ui/remote/snode1/    共享端口上的 route —— 路径被改写
```

## 两条路为什么都在

远端那个界面的产物里，绝对前缀是**构建期烘死**的：`vite.config.ts` 的
`base: "/ui/"` 会出现在三个地方——`index.html` 里的 `src`/`href`、CSS 的 `url()`、
以及 JS 里 `import.meta.env.BASE_URL + "api"` 折出来的那个**字符串**。挂在一条路径
底下就绕不开改写。

- **转发端口**（相当于 `ssh -L`）：路径一个字节都不动，远端界面原样可用。**保真。**
  代价是本机多占一个端口。
- **route**：不占端口，任何路径都能到达它。代价是改写——**尽力而为**，不是等价物。

## route 到底改了些什么

改写是**一处前缀替换**，因为远端那个绝对前缀只有一个字面量 `/ui/`。但有三处值得
单独说，它们各自错过一次就很难查：

**① JS 产物里的 API 基址。** `import.meta.env.BASE_URL + "api"` 在构建期折成了
`const Fn="/ui/api"`，写在 bundle 里面。这**不是**一个资源引用（那种地址在 HTML
那一遍已经改过），而是一个运行期用来拼 URL 的值。不改它的后果是：隧道里那个页面
照着**本机自己**的 `/ui/api` 发请求——界面渲染得漂漂亮亮，**每一个数字都是错的
那台机器的**。这比白屏糟得多，因为看起来是好的。

**② 重定向（`Location`）。** 远端对 `/ui`（没有尾斜杠）会 302 到 `/ui/`，那个地址
在本机上是**你自己的界面**。不改写的症状是：点一下，从一个远端界面跳到了本地界面，
而两者长得几乎一样。这是整套改写里唯一一处看不出来的错。

**③ 外链不能碰。** `https://example.com/ui/x` 里的 `/ui/` 不是远端自己的路径。裸替换
会把它悄悄改成 `/ui/remote/<id>/x`——**把用户的出站链接指回我们自己**，而这件事错了
没有任何症状。所以替换前会往回看到分隔符，带 scheme 或协议相对的一律跳过。

改写的对象是 `text/html`、`text/css`、`text/javascript`（按内容类型判），
带 `Content-Encoding` 的一律不动（压缩过的正文里没有明文路径可改）。

**会坏的地方，说在前面**：一个**运行期才拼出绝对地址**的界面（不是从那个 `/ui/`
字面量来的）过不来。所以 route 上看着不对时，用转发端口。

## 认证与信任

**只认密钥文件与 ssh-agent，不做密码。**

这不是省事，是一条有后果的取舍：正因为配置里没有任何秘密，那份 target 列表才可以
整份住在 `state.json`（0660、web 界面能编辑）。`identity` 存的是**路径**，
`host_key` 存的是**策略**，两者都不是凭据。做密码的话，它要么落进那个谁都能读的
文件里，要么另开一个只有命令行能碰的存储——后者会把「web 界面能配」砍掉一半。

- 身份文件：显式给了 `identity` 就**只**试那一个（你指的是哪把钥匙就是哪把）；
  没给就按 `~/.ssh/id_ed25519`、`id_ecdsa`、`id_rsa` 的顺序，再叠上 ssh-agent。
- **主机密钥默认严格校验**（`host_key: strict`）。不认识那台机器就拒，错误里写清
  下一步：先在终端 `ssh <host>` 一次，或者把这个 target 设成 `accept-new`。
- `accept-new` 的语义是「**没见过就记**」，不是「变了也认」——记录里对不上时**照拒**，
  并且**不会**覆盖。变了就认是最危险的那种静默降级。
- 记下一条新主机密钥时**每次都会打日志**：信任一台机器是一个事件。
- `~/.ssh/config` 里 `Host` / `HostName` / `User` / `Port` / `IdentityFile` 会生效。
  `ProxyJump`、`ProxyCommand`、`Match` 这些**认不出但会影响连通性**的键会**报出来**：
  静默忽略的后果是用户以为自己在走跳板机、实际直连了一个不可达的地址，而那看起来
  像网络问题。

## 连接的生命周期

默认是**懒的**：第一个请求才拨，连接池复用，空闲 `idle_seconds`（默认 300）之后断开。
`persistent: true` 的 target 在守护进程起来时就连，断了按 1s→30s 退避重连。

复用不是优化，是这个功能有没有实用价值的决定因素：一次 SSH 握手是**公钥运算**
（内网 50–200ms），比远端界面自己的一次 API 往返还贵。每个请求拨一次的话，打开一张
控制台要付几十次握手的钱。

守护进程每 2 秒让运行态追上配置，所以你在界面上改完，两秒内生效；它同时做空闲回收
和 keepalive 探活（一条被对端或 NAT 悄悄掐掉的连接，不探的话症状是「第一个请求卡住」
而不是「自动重连之后成功」）。

## 命令行

```bash
newgate tunnel                       # = ls，列出配置与两条路的地址
newgate tunnel add <id> --host H [--user U] [--port 22] [--remote-port 8899] \
                        [--local-port 0] [--identity PATH] [--persistent] \
                        [--host-key strict|accept-new]
newgate tunnel rm <id>
newgate tunnel up <id>               # 让它常驻（改配置，守护进程两秒内跟上）
newgate tunnel down <id>             # 改回按需拨号
newgate tunnel test <id>             # 真拨一次，逐步报出卡在哪
```

**`ls` 刻意不报连接状态**：每一条 `newgate …` 都是另一个进程，它有自己的连接池，
而那个池永远是空的——在那里打印「已连接」会是一句彻底的假话（真的连接在守护进程
里）。要看谁连着，看网页界面上那张表，它是 live 的。

`tunnel test` 是这一族里唯一**不需要守护进程**的：它自己在当前进程里拨号，逐步报出
`dns` / `ssh` / `remote` 哪一步坏了。连不上时先跑它——一次成功的 SSH 与「SSH 通了但
远端那个端口没人听」是完全不同的两件事，而它们的下一步动作也不同。

## 界面

`/ui/remote/` 是索引页（朴素 HTML，不依赖前端产物——它在 web-dashboard 缺席的装配里
也成立）。左侧栏的「路由 / 远端」一节里有两张卡：

- **目标**：可写的配置卡，增删改都在这里（与别的配置卡同一套「整份替换」契约）。
- **连接**：live 的状态表，两条路的地址都是**能点的链接**（新标签页打开——这是个带
  草稿的单页应用，链接把当前页顶掉就等于把没保存的编辑丢了）。转发端口没起来的那一
  格**不给链接**：点开就是连不上的地址，比没有链接更让人以为是自己配错了。

## 安全边界

- 本地这道门是**唯一**一道：只看 `Host` 头，只放行回环地址与 `localhost`（与架构图
  那道门同一条判据——挡 DNS rebinding 要看 Host，不是看对端地址）。远端那道门查的是
  它自己收到的 Host，而那个头是我们保留下来的浏览器填的那个。
- 转发端口**只绑 `127.0.0.1`，没有配置项可改**。这个端口背后是一台**没有 Host 门**的
  远端界面，绑到别的地址等于把它对局域网敞开。要给别人用，该让别人自己建一条
  tunnel（他们有自己的 SSH 凭据）。
- route 只转发**远端的 `/ui` 那一棵**：远端的 `/__newgate`（控制面）与 `/v1`（数据面）
  都够不到。
