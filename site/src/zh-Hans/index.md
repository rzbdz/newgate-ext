# 为 vibecoding 而生的最佳网关

## <small>01</small> 接管你的 CLI，而 CLI 毫无察觉

一个 PATH shim，加上客户端自己的配置被就地改写——环境变量静默注入，改之前先按字节
备份。装一次，此后不用再手改配置，也不用重开会话。

## <small>02</small> 换哪个 API 应答是一条命令

不是一次迁移。下一发请求就走新链，客户端继续跑着，它的配置没被动过，旧上游离你
一条命令：

```bash
newgate --set-profile work
```

## <small>03</small> 该全局就全局，小活可以临时来

档位配一次，所有客户端跟着走。某个小任务想换个模型，就在那一次调用上换：

```bash
newgate claude --profile=cheap
```

什么都不改全局的。这个选择走在**请求路径**里，所以同时跑着的两个客户端永远不会
拿错对方的选择。

## <small>04</small> 单个上游挂掉，不等于你挂掉

每个档位都是一条**有序的候选链**：你的规则优先，然后是预测的首字节时间。每一次跳过
都有解释，每一次改道都记账。

## <small>05</small> 出了什么事，看得见

```bash
newgate metrics     # 按上下文大小分的延迟、改道次数、首字节超时、字节改写，每个计数器都带一句话
newgate logs -f     # 跟着看代理日志
newgate debug on    # 把每一发请求都倒出来
newgate doctor      # 出问题时先跑它
```

## <small>06</small> 同一份画面，浏览器里也有一份

`newgate web` 打出地址——就挂在网关已经在听的那个端口上。档位绑定就地编辑、运行期
开关直接拨、计数器、日志尾巴、绑定健康、此刻谁在走网关，都在那儿。每一次改动都走
**命令行用的那条写入路径**，并带上你加载时的那份修订：你在看页面时命令行改过的文件，
会摆成一个冲突让你决定，而不是被盖掉。

## <small>07</small> 升级不会打断你

`newgate upgrade` 拿到新二进制（GitHub Release，或者开发机上从本地仓库现编），
试跑一次、换上，然后 `newgate restart` 把监听 socket 交给它，并把在途的请求排干——
流式的也算，所以在一个很长的 agent 会话中间换版本是安全的，哪怕那个会话正走在这条
被替换掉的网关上。`newgate upgrade@v0.9.0` 钉到某个版本；换坏了
`newgate self-update rollback` 一步换回去。

## <small>08</small> 只开 SSH 的机器，界面也够得到

内网里常有一类机器：只开 SSH。newgate 在那台机器上照常跑着，网页界面在它的
`127.0.0.1:8899` 上听着，但你够不到。`modules/ssh-tunnel` 穿过 SSH 去把它取回来，
一次给两条路：一个**本地转发端口**（路径一个字节都不动，远端界面原样可用），以及
共享端口上的一条 **route**（不占端口，路径要改写，所以只能尽力而为）。两条都建立在
同一条按需拨号、空闲释放的 SSH 连接上。

**转发端口那条才是诚实的**，这句话值得说两遍：route 上的改写有一处很容易漏——
`import.meta.env.BASE_URL` 在构建期就被折进了 JS 产物（`const Fn="/ui/api"`），
不改它，那个页面会去问**你这台**网关要数据，于是界面渲染得漂漂亮亮而每一个数字都
是错的。所以两条路都在，而不是只做省事的那条。

## <small>09</small> 上游的怪癖是模块，不是 `if`

DeepSeek 的 reasoning 回传与尾部形状、GLM 的思维链回传、Claude Code 的后台分类器
调用——每个都写了它存在是为了防住哪个故障，可以在运行期开关。客户端 × 模型的桥也是
模块（Claude Code × DeepSeek、Codex × DeepSeek、OpenCode 里 Oh My OpenAgent 的
槽位）。读一个，换掉它，或者给一个我们从没听说过的上游写补丁。

## <small>10</small> 先探活，再相信它

`newgate probe` 对每条候选真打一发最小请求：通不通、说哪种方言、延迟多少，还顺手
记下这家上游的怪癖（哪些请求形状会 400）。探明的结论会落盘，下一轮不再重复花
token；网页的健康表与命令行看的是同一份账本。

## <small>11</small> 指纹：上游真的是你以为的那个模型吗

`newgate verify` 不问模型「你是谁」——它当然会照着你写的名字回。它让模型吐几百个
1–355 的整数，再拿这些数字和模型指纹参考库比一遍，报出参考库认为的模型；binding
写的名字对不上时给 warning，同族也算 warning。网页上多了一页**指纹**：按档位文件筛、
每条 binding 一个「验证」按钮，还能直接挑一家上游、一个模型现场取指纹；配置页的
模型下拉里也会带出上一次验到的结论。

参考库是动态数据：默认每 2 小时检查一次新版本，也可以 `newgate upgrade` 手动刷新
（`upgrade` 是各模块登记升级动作的入口，二进制本身也是其中一项）。
指纹由 [lm-detector](https://github.com/Ikaleio/lm-detector) 提供（MIT），参考数据
来自 [lm.ikale.io](https://lm.ikale.io/docs/sdk)。谢谢这个项目。

### 连 `gateway` 和 `cli` 都是模块

一个模块就是一个目录、一个导出的 `New()`。内核那一栏里住着网关、熔断、终端界面、
接管；右边那一栏是这个发行版加的：客户端接入、上游怪癖、网页界面、三套皮肤。**两栏
是同一种东西**——分栏只看它由哪个仓库出货，不看它被允许做什么。规格书（8 行 JSON）
没写进去的模块，二进制里根本没有它，不是一个运行期开关。上面那个框子的第二页
（装配图）就是它。
